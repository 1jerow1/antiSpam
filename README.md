# antiSpam

Telegram-бот для модерации барахолки: удаляет из чата всё, что **не является продажей товара** —
объявления о работе/подработке, услуги, крипту, обмен, рекламу и ссылки.

Классификация — **гибридная**, с возможностью перейти на чистый ML:

- Основной путь — собственный обучаемый ML-классификатор (TF-IDF + логистическая регрессия,
  scikit-learn), который работает мгновенно и без внешних сервисов.
- Пока модель ещё не обучена или не уверена в конкретном сообщении — решение принимает
  локальная LLM через [Ollama](https://ollama.com/) (`llama3:8b`), как раньше.
- Каждое решение Ollama автоматически сохраняется как новый обучающий пример, поэтому
  датасет пополняется сам по себе по мере работы бота, а ML-модель постепенно берёт на себя
  всё больше решений — Ollama дёргается всё реже.
- Когда модель набрала достаточно данных и прошла калибровку, Ollama можно отключить совсем
  (`USE_OLLAMA=false`) — так бот работает на Railway и других серверах без GPU
  (см. [«Режим только ML»](#режим-только-ml) и [«Деплой на Railway»](#деплой-на-railway)).

## Как это работает

1. Пользователь пишет сообщение в чат.
2. Бот пропускает без проверки: администраторов чата, пользователей из whitelist и сообщения с фото.
3. Если ML-модель обучена и `P(NOT_SALE)` выше откалиброванного порога удаления — сообщение
   удаляется сразу, без Ollama. Если модель уверена, что это объявление (≥ `ML_CONFIDENCE_THRESHOLD`),
   оно остаётся, тоже без Ollama. Во всех остальных случаях текст уходит в Ollama с промптом-инструкцией
   модератора, и её ответ (`SALE`/`NOT_SALE`) попадает в датасет (`dataset.jsonl`) как новый
   обучающий пример (только если такого текста там ещё нет — повторы спама в файл не дописываются).
4. `NOT_SALE` → сообщение удаляется. `SALE` или ошибка Ollama → сообщение остаётся (fail-safe).
5. Администратор может исправлять ошибки классификации командой `/correct` — эти исправления
   тоже идут в датасет и имеют приоритет над автоматическими метками Ollama при обучении.
6. Когда датасет накопил достаточно примеров обоих классов — `/train` обучает модель заново.

Дополнительно:

- **LRU-кэш** ответов Ollama (одинаковые тексты не гоняются повторно).
- **Кэш списка админов** чата на 5 минут.
- **Ограничение параллелизма** запросов к Ollama (семафор на 3).
- **Дневная статистика** (`stats.json`): сколько проверено / оставлено / удалено / решено ML / решено Ollama.

### Важно про приватность

`dataset.jsonl` хранит **тексты сообщений пользователей** (нужно для обучения модели) —
в отличие от `stats.json`, это не просто счётчики. Файл добавлен в `.gitignore` и не должен
попадать в репозиторий. Он живёт только там, где запущен бот (локальная машина или том
Railway), и передаётся только вам самим — например, личным сообщением боту.

## Требования

- Python 3.11+
- [Ollama](https://ollama.com/) с загруженной моделью:
  ```bash
  ollama pull llama3:8b
  ```
- Бот добавлен в чат **администратором** с правом удалять сообщения.
- В [@BotFather](https://t.me/BotFather) для бота **выключен privacy mode**
  (`/setprivacy` → `Disable`), иначе он не видит обычные сообщения.

## Установка

```bash
git clone https://github.com/1jerow1/antiSpam.git
cd antiSpam
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux / macOS
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env` и заполните:

```bash
copy .env.example .env        # Windows
# cp .env.example .env         # Linux / macOS
```

| Переменная      | Обязательна | Описание                                            |
|-----------------|-------------|----------------------------------------------------|
| `BOT_TOKEN`     | да          | токен бота от @BotFather                            |
| `ADMIN_ID`      | да          | ваш Telegram user id (узнать у @userinfobot)        |
| `OLLAMA_URL`    | нет         | адрес Ollama API (по умолчанию localhost:11434)     |
| `OLLAMA_MODEL`  | нет         | имя модели (по умолчанию `llama3:8b`)               |
| `MAX_TEXT_LENGTH` | нет       | до скольких символов обрезать текст (по умолчанию 500) |
| `DATASET_FILE`  | нет         | путь к датасету обучающих примеров (по умолчанию `dataset.jsonl`) |
| `MODEL_FILE`    | нет         | путь к обученной ML-модели (по умолчанию `model.joblib`) |
| `MODEL_META_FILE` | нет       | путь к метаданным обучения (по умолчанию `model_meta.json`) |
| `ML_CONFIDENCE_THRESHOLD` | нет | гибрид: минимальная уверенность ML-модели в SALE, чтобы оставить сообщение без Ollama (по умолчанию `0.85`) |
| `USE_OLLAMA`    | нет         | `false` — чистый ML без Ollama (по умолчанию `true`, гибрид) |
| `ML_DELETE_THRESHOLD` | нет   | порог P(NOT_SALE) для удаления в режиме без Ollama; по умолчанию подбирается при обучении |
| `ML_MIN_SALE_EXAMPLES` | нет  | минимум SALE-примеров, чтобы обучение выдало порог удаления (по умолчанию `100`) |
| `DATA_DIR`      | нет         | каталог для `stats.json`, `whitelist.json`, датасета и модели (по умолчанию текущая папка; на Railway — путь тома) |

## Запуск

```bash
python antiSpam.py
```

На Windows можно использовать `run.bat` — он дожидается готовности Ollama и запускает бота.

### Обучение ML-модели

Изначально `model.joblib` не существует — все решения принимает Ollama, а её ответы копятся
в `dataset.jsonl`. Когда там наберётся достаточно примеров обоих классов (SALE и NOT_SALE):

```bash
python train_model.py
```

или прямо в чате командой `/train`. Модель подхватится сразу, без перезапуска бота, и дальше
уверенные решения по новым сообщениям она будет принимать сама, а Ollama останется резервным
вариантом для неуверенных случаев. Периодически переобучайте модель заново (`/train`) по мере
роста датасета — качество классификации будет расти вместе с ним.

Если один и тот же текст встречается с разными метками, при обучении побеждает более надёжный
источник: `admin` (ваша правка через `/correct`) > `claude` (метки, проставленные вручную при
проверке датасета ассистентом) > `ollama` (решение LLM) > `history` (импорт из истории чата).

### Импорт SALE-примеров из истории чата

SALE-объявления в реальном трафике редки (несколько процентов), поэтому набирать их только
через Ollama долго. Ускорить можно импортом из экспорта чата: сообщения, которые бот удалил,
в экспорте отсутствуют, а уцелевшие — кандидаты в SALE.

**Кандидаты, но не готовые SALE.** Слабая модель пропускает много спама (подработки, «есть тема»,
курсы, посредники, приветствия): в одном реальном чате из уцелевших сообщений реальными
объявлениями оказалось лишь около четверти. Если записать их в SALE как есть, порог удаления
придётся поднять почти до потолка, и модель будет узнавать лишь малую долю спама.
Поэтому после импорта обязательна проверка вторым, более сильным вердиктом (шаг 4).

1. Telegram Desktop → меню чата → **Export chat history**, формат **JSON** (не HTML),
   без медиа. Экспорт должен охватывать период, когда бот уже работал: до этого спам никто
   автоматически не удалял, и «уцелевшее» не значит «проверенное».
2. Сначала посмотрите, что будет импортировано:
   ```bash
   python import_history.py result.json --since 2026-04-11 --exclude-user 123456789 --dry-run
   ```
   `--since` — дата, с которой бот работает в чате; `--exclude-user` (можно несколько раз) —
   админы чата и whitelist, чьи сообщения бот не проверяет.
3. Уберите `--dry-run` — примеры допишутся в `dataset.jsonl` (резервная копия — `dataset.jsonl.bak`).
4. Проверьте все SALE-метки второй моделью (нужна Ollama и модель посильнее, например
   `ollama pull qwen2.5:14b-instruct`):
   ```bash
   python verify_labels.py --dry-run          # посмотреть итог
   python verify_labels.py                    # записать исправления
   ```
   Всё, что вторая модель считает не объявлением (подработка, услуга, курс, крипта…), станет
   NOT_SALE; покупка вещи, как и раньше, остаётся объявлением. Проверенные примеры повторно
   не проверяются.
5. Переобучите модель: `python train_model.py` или `/train`.

Пропускаются служебные сообщения, ответы на чужие сообщения, тексты короче 20 символов,
сообщения с фото (бот их не проверяет; `--include-photos` включает их) и всё, что уже есть
в датасете. Файлы экспорта содержат личные данные — не кладите их в репозиторий
(`result.json` и `ChatExport_*/` уже в `.gitignore`).

### Режим только ML

С `USE_OLLAMA=false` Ollama не используется вообще. Бот удаляет сообщение только если
модель уверена, что это не продажа: `P(NOT_SALE) ≥ порог`. Всё сомнительное остаётся —
как и раньше, лучше пропустить спам, чем удалить настоящее объявление.

Порог подбирает сам `/train`: по кросс-валидации берётся самый низкий порог, при котором
ложно удаляется не больше 1% настоящих объявлений (SALE), но не ниже 0.9 — кросс-валидация
на датасете с близкими копиями оптимистична, поэтому запас нужен. Чтобы такая оценка была честной,
нужно минимум `ML_MIN_SALE_EXAMPLES` (100) SALE-примеров — иначе порог не выдаётся,
`/mlstats` пишет «калибровка не пройдена», и бот **ничего не удаляет**. Итоговое качество
видно в ответе `/train` и в `/mlstats`: порог, число ложных удалений на кросс-валидации и
доля спама, которую модель распознаёт сама.

Без Ollama датасет сам не пополняется. Пропущенный спам исправляйте командой
`/correct spam` (реплаем — сообщение удалится и запомнится), ошибочно удалённое —
`/correct <id> sale`, и периодически запускайте `/train`.

## Деплой на Railway

Railway не умеет запускать Ollama (нет GPU), поэтому там бот работает в режиме только ML.
Сначала обучите модель (импорт истории + `/train` либо `python train_model.py` локально),
убедитесь, что калибровка пройдена, и только потом переезжайте.

1. **Сервис.** В Railway: New Project → Deploy from GitHub repo → выберите репозиторий.
   Конфиг уже лежит в `railway.toml` (Railpack, запуск `python antiSpam.py`), версия
   Python — в `.python-version`.
2. **Том.** В сервисе: Settings → Volumes → New Volume, mount path `/data`. Без тома файловая
   система стирается при каждом деплое, и вы потеряете датасет, модель и статистику.
   Бот сам берёт путь из `RAILWAY_VOLUME_MOUNT_PATH`.
3. **Переменные** (Variables): `BOT_TOKEN`, `ADMIN_ID`, `USE_OLLAMA=false`.
4. **Датасет.** Отправьте файл `dataset.jsonl` личным сообщением боту (с вашего аккаунта,
   `ADMIN_ID`) — бот допишет его в датасет на томе. Затем выполните `/train` и проверьте
   `/mlstats`: режим должен показать «только ML: удаление при P(NOT_SALE) ≥ …».
   Модель обучается на сервере, поэтому переносить `model.joblib` не нужно.
5. **Остановите локального бота.** Два экземпляра с одним токеном не могут одновременно
   получать обновления Telegram (ошибка `TelegramConflictError`).

Если запись в `/data` падает с ошибкой прав доступа, добавьте переменную `RAILWAY_RUN_UID=0`.

## Команды администратора

| Команда           | Где            | Действие                                             |
|-------------------|----------------|-----------------------------------------------------|
| `/whitelist_add`  | реплаем на сообщение пользователя | добавить пользователя в whitelist (его сообщения не проверяются) |
| `/stats`          | в чате         | статистика за сегодня (включая разбивку ML / Ollama) |
| `/mlstats`        | в чате         | состояние ML-модели: режим, точность, порог удаления и его калибровка, размер датасета |
| `/train`          | в чате         | (пере)обучить ML-модель на текущем датасете и подобрать порог удаления |
| файл `dataset.jsonl` | личкой боту | дописать присланный датасет в датасет бота (для переноса на сервер) |
| `/pending`        | в чате         | последние удалённые сообщения с их ID (для `/correct`) |
| `/correct sale\|spam` | реплаем на сообщение | исправить классификацию: пометить как SALE/NOT_SALE и добавить в датасет (спам при этом удаляется) |
| `/correct <id> sale\|spam` | в чате   | исправить уже удалённое решение по ID из `/pending` (например, если удалили не спам) |
